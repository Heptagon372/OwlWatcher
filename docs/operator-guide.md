# 감독관 지침

한 장짜리로 유지한다. 시험장에서 읽을 문서라 길면 안 읽힌다.

---

## 알림을 읽는 법

문구는 **등급을 먼저** 말한다.

```
[확정] 좌석 17 · 09:58 ~/Downloads/helper.exe 실행(미서명, 커널 기록)
       → 화면 오른쪽 위 상태 영역과 작업표시줄 확인
```

| 배지 | 뜻 | 무엇을 해야 하나 |
|---|---|---|
| **[확정]** P0 | OS 커널·학교 서버가 기록했거나 우리 코드의 검증이 실패했다. 학생 기기가 위조할 수 없다. | 좌석으로 간다. 화살표 뒤에 적힌 것을 학생과 함께 확인한다. |
| **[정황]** P1 | 정상 사용에서 잘 나오지 않는 조합. 개별로는 설명 가능하다. | 한 번 가서 확인하면 끝난다. 같은 프로그램에 정황이 2건 이상 겹치면 빨간불이 된다. |
| **[참고]** P2 | 단독으로는 아무 의미 없다. | 아무것도 하지 않는다. 리포트에서 맥락으로만 쓰인다. |

**중요.** [정황]은 부정행위가 아니다. "확인해 달라"는 요청이다.
학생에게 그렇게 말하면 된다 — *"프로그램 하나가 목록에 없어서 확인 왔습니다."*

## 좌석 색

| 색 | 상태 |
|---|---|
| 회색 | 미접속 |
| 초록 | 감시 중 · 보호 유효 |
| 노랑 | 정황 있음 — 한 번 확인 |
| 빨강 | 확인 필요 — 좌석으로 이동 |
| 검정 | 하트비트 30초 끊김 — 에이전트가 죽었거나 네트워크 문제 |

## 시험 시작 절차

1. 학생이 에이전트를 실행한다 → 동의 화면 → **사전 점검**이 자동으로 돈다
2. 사전 점검을 통과하지 못하면 **시작할 수 없다.** 보호가 꺼진 채로 시험이 시작되지 않도록 막아 둔 것이다
   - 실패 사유가 화면에 나온다. 대개 이 기기에서 캡처 차단이 안 되는 경우다
   - 그 좌석은 L0(점검만)으로 응시시키고 리포트에 남긴다
3. 좌석 색이 **파랑(시작 대기)** 이 되면 콘솔에서 `시험 시작` 을 누른다
   - 콘솔이 없으면 학생 화면의 **6자리 코드**를 감독관이 확인하고 세션 코드를 입력한다
   - **학생은 이 단계를 건너뛸 수 없다**

## 자주 나오는 것

| 알림 | 대개 이것 | 조치 |
|---|---|---|
| 상태 영역 항목의 소유 프로세스가 허용목록 밖 | 국내 은행·공인인증 보안 프로그램, 제조사 유틸 | 확인 후 `이 앱 허용(이 세션만)` |
| 창 없이 상주하는 프로세스 | 클라우드 동기화, 백신, 게임 런처 | 같음 |
| 시험망 비콘에 도달하지 못함 | 학교망 장애 | **조치 아님.** 참고 등급이다 |
| 시험망 밖 목적지에 연결됨 | 휴대폰 테더링·핫스팟 | 빨간불. 확인 필요 |
| 시험 창 캡처 보호가 꺼짐 | 누군가 보호를 되돌렸다 | **즉시 좌석으로.** 가장 강한 신호다 |

한 시험에서 같은 프로그램이 여러 좌석에 반복해서 뜨면, 그건 학생 문제가 아니라
**허용목록 문제**다. 시험 후 `ExamCheck --emit-allowlist` 로 초안을 만들어 학교 공용 목록에 반영한다.

## 하면 안 되는 것

- **아이콘 모양으로 판단하지 않는다.** 이 도구는 아이콘 모양을 보지 않고, 감독관도 그러면 안 된다.
- **[정황]을 처분 문서에 사실로 쓰지 않는다.** 리포트가 P0/P1/P2 를 세 절로 나눠 주는 이유다.
- **학생 화면을 들여다보지 않는다.** 알림이 "어디를 보라"고 말해 준다. 그것만 본다.
- **이 도구의 결과로 부정행위를 단정하지 않는다.** 확인 요청과 증거일 뿐이다.

## 못 막는 것 (학생에게도 알리는 편이 낫다)

휴대폰 · 2차 기기 · AI 안경 · 하드웨어 캡처 카드 · 종이 쪽지. 소프트웨어로 막을 수 없다.
OwlWatch 는 **노트북 상주형 도구**의 비용과 발각 확률을 올리는 도구다.

## 시험이 끝나면

1. 학생이 에이전트를 닫으면 캡처 차단이 해제되고 세션 키가 삭제된다
2. 콘솔에서 리포트를 내려받는다 — P0/P1/P2 가 세 절로 분리돼 있다
3. 이의제기가 없으면 30일 후 자동 삭제된다
